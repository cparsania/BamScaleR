# BamScaleR benchmark harness

This folder holds two complementary, budget-aware benchmark drivers and the
assets used to summarise their results. Nothing here is loaded at package run
time — it exists to reproduce the numbers reported in the benchmark article.

- **`run_server_benchmark.R`** — read-pattern micro-benchmarks (`step1` /
  `galignments` / `seqqual`) against `Rsamtools` and `GenomicAlignments`.
- **`run_workflow_benchmark.R`** — end-to-end workflow benchmarks
  (coverage → bigWig, ATAC fragment-size QC) reported as a read / compute /
  write phase decomposition so the Amdahl bound on the end-to-end speedup is
  explicit.
- **`bench_common.R`** — shared helpers + the phase-aware timing engine sourced
  by the workflow driver (defines functions only; no side effects on source).
- **`download_atac_data.R`** — fetch + index a public paired-end ATAC-seq
  dataset; run once before the ATAC workflow (no ATAC data ships with the host).
- **`select_encode_atac.R`** — select a corpus of public ENCODE ATAC-seq BAMs
  from the ENCODE portal and write a manifest (accession, md5, URL) that
  `download_atac_data.R --manifest=` consumes.
- **`merge_runs.R`** — merge the result directories of separately run stages
  into one directory shaped like a single harness run.
- **`samtools_reference.sh`** — time `samtools view -c` on the same BAMs as an
  object-free raw-decode reference.

Results are written as machine-readable CSVs to `--outdir` (e.g. a git-ignored
`benchmark_results/`) and are not committed. The narrative summary and figures
live in `vignettes/benchmark-results.Rmd` (the pkgdown "Benchmarks" article),
which reads a small subset of one run's results shipped in `inst/extdata/`.
`inst/scripts/make_benchmark_extdata.R` regenerates those files from a finished
run directory, and its header records the commands that produced the published
run.

## Requirements

The scripts here need, in addition to BamScaleR and its own dependencies
(`Rsamtools`, `GenomicAlignments`, `BiocParallel`, ...):

| Requirement | Kind | Used by | Needed for |
| --- | --- | --- | --- |
| `chipseqDBData` (with `ExperimentHub`) | R package | `run_server_benchmark.R`, `run_workflow_benchmark.R` | default BAMs (`H3K9acData()`) when no `--bam-dir` is given |
| `rtracklayer` | R package | `run_workflow_benchmark.R` | bigWig export in the coverage workflow (required) |
| `ATACseqQC` | R package | `run_workflow_benchmark.R` | `--atac-anchor=true` check against `ATACseqQC::fragSizeDist` (skipped if absent) |
| `jsonlite` | R package | `select_encode_atac.R`; `download_atac_data.R` | ENCODE portal queries (required by the former; only for `--experiment=` in the latter) |
| `ggplot2` | R package | `run_server_benchmark.R` | `plot_*_scaling.png` (skipped if absent) |
| `samtools` | command-line tool | `samtools_reference.sh` | raw-decode reference |
| `bash`, `bc`, `awk`, GNU `stat`/`du`/`date` | command-line tools | `samtools_reference.sh` | timing and arithmetic |
| `megadepth` | command-line tool | `run_workflow_benchmark.R` | optional `--megadepth-bin=` context arm of the bigWig workload |
| internet access to `www.encodeproject.org` | network | `select_encode_atac.R`, `download_atac_data.R` | corpus selection and download |

Install the R packages with:

```r
BiocManager::install(c("chipseqDBData", "ExperimentHub", "rtracklayer",
                       "ATACseqQC", "jsonlite", "ggplot2"))
```

These requirements are intentionally **not** declared in the package
`DESCRIPTION`. The scripts are run by hand and are never run by
`R CMD check`, the vignettes or the unit tests, so none of these packages or
tools is needed to install, check or use BamScaleR. (`rtracklayer` and
`ggplot2` do appear in `Suggests`, but for the unit tests and the intro
vignette's bigWig check, and for the benchmark vignette's figures,
respectively, not for these scripts.)
`inst/scripts/make_benchmark_extdata.R` uses base R only.

## Results

The results of the canonical run (2026-10-08, BamScaleR 0.99.1, the 25-file
ENCODE ATAC-seq corpus) ship with the package as CSV files in `inst/extdata/`,
generated by `inst/scripts/make_benchmark_extdata.R`. The vignette
`vignette("benchmark-results", package = "BamScaleR")` computes all of its
tables and figures from those files. No speedups are repeated here, so this
file cannot drift out of step with the data.

## Read-pattern micro-benchmarks — `run_server_benchmark.R`

```bash
Rscript inst/benchmarks/run_server_benchmark.R \
  --profile=balanced --budget-threads=48 --max-threads=48 \
  --bam-dir=/path/to/bam_directory --n-files=12 \
  --bp-backend=snow --iterations=5 --outdir=benchmark_results
```

If no `--bam-dir` is given, BAMs are resolved from `chipseqDBData::H3K9acData()`.

**Tracks.** `fair` = comparator-safe runs used for BamScaleR vs
Rsamtools/GenomicAlignments comparisons; `optimized` = BamScaleR-only runs
(compact `seq/qual`). Report sections that claim cross-package comparison use
only the `fair` track.

**Profiles.** `bamscale_showcase` (default, `step1`-focused), `balanced`
(broader workloads for fair comparison), `full` (widest grid).

**Budget model.** `--budget-threads` is the total compute budget
(`min(48, cores)` for showcase/balanced, `cores` for `full`); `--max-threads`
is the per-run thread ceiling. Multi-file BamScaleR uses a balanced split:
`threads_each = floor(max_threads / workers)`, so total ≈ `workers * threads_each`.

**Useful options:** `--profile`, `--budget-threads`, `--max-threads`,
`--threads` (single-file grid), `--workers` (multi-file grid),
`--single-workloads` / `--multi-workloads=step1,galignments,seqqual`,
`--seqqual-compact=true|false`, `--include-rsamtools`, `--include-galignments`,
`--ensure-index`, `--allow-repeat-files`, `--bp-backend`, `--iterations`.

## End-to-end workflow benchmarks — `run_workflow_benchmark.R`

BamScaleR replaces exactly the BAM-read step of each workflow; the compute and
write steps are byte-identical work on both arms. Single-file cases sweep the
OpenMP thread axis with full per-phase timing; multi-file cases sweep the
`BiocParallel` worker axis at a fixed core budget.

```bash
# Coverage workflow (uses the same chipseqDBData BAMs by default)
Rscript inst/benchmarks/run_workflow_benchmark.R \
  --include-coverage=true --include-atacqc=false \
  --threads=1,4,12,24,48 --workers=1,2,4,8,12 \
  --n-files=12 --budget-threads=48 --max-threads=48 \
  --bp-backend=snow --iterations=5 --write-bigwig=true \
  --outdir=benchmark_results

# ATAC fragment-size QC (fetch data first, once)
Rscript inst/benchmarks/download_atac_data.R \
  --experiment=ENCSRxxxxxxx --dest=/path/to/atac/bams
Rscript inst/benchmarks/run_workflow_benchmark.R \
  --include-coverage=false --include-atacqc=true \
  --atac-bam-dir=/path/to/atac/bams \
  --threads=1,4,12,24,48 --iterations=5 --outdir=benchmark_results
```

`download_atac_data.R` accepts `--manifest=` (a manifest written by
`select_encode_atac.R`, optionally filtered with `--role=single|multi`; md5
checksums are verified), `--urls=`, `--experiment=ENCSR…` (resolved via the
ENCODE REST API), or `--files=ENCFF…`; it indexes each BAM and verifies paired-end
reads.

## Outputs

Read-pattern runs: `summary.csv` (per-case stats), `iterations.csv`,
`files.csv`, `config.txt`, `sessionInfo.txt`, and (with `ggplot2`)
`plot_single_scaling.png` / `plot_multi_scaling.png`.

Workflow runs add per-phase columns (`read_s`, `compute_s`, `write_s`,
`total_s`, plus per-phase CPU) and a correctness table recording the
`identical()` / byte-identical checks against the standard tools.

## Regenerate the vignette data

```bash
Rscript inst/scripts/make_benchmark_extdata.R benchmark_results/<run> inst/extdata
```

`<run>` is a finished run directory holding `RUN_NOTES.md`,
`encode_atac_manifest.csv` and the `merged_read/`, `merged_cov/` and
`merged_atac/` directories written by `merge_runs.R`.

## Render the report

The vignette reads its data with `system.file()`, so install the package from
this source tree first:

```bash
R CMD INSTALL .
Rscript -e "rmarkdown::render('vignettes/benchmark-results.Rmd')"
```
